# App instructions

An offline-first mobile app in **Material 3 Expressive**: Vue 3 + Capacitor over a local SQLite
database that screens read reactively. Framework7 runs underneath as the navigation engine only.
Generated from `@cavulsqa/template-m3e-app`.

**SQLite is the source of truth.** There is no server in this template. A screen reads the local
database and a write to the local database refreshes it. If you add a backend, it syncs _into_
SQLite — it does not become the thing screens read.

## Stack

Vue 3.5 `<script setup lang="ts">` · `@cavulsqa/m3e-vue` components on `@cavulsqa/m3e` tokens ·
Framework7 9 core (router, views, pages - nothing visual) · Capacitor 8 (Android first) · Kysely over
SQLite in an OPFS worker · vue-i18n · Tailwind 4 mapped to M3 tokens · Google Sans Flex · Material
Symbols · Vite+ (`vp`).

| Package                  | What it gives you                                                    |
| ------------------------ | -------------------------------------------------------------------- |
| `@cavulsqa/m3e`          | 2025-spec colour, the 35 shapes, springs, wavy progress, every token |
| `@cavulsqa/m3e-vue`      | The `M3*` components, overlay services, theme application            |
| `@cavulsqa/mobile-db`    | The OPFS worker dialect, migrations, transaction-aware writes        |
| `@cavulsqa/reactive-db`  | Change bus, result cache, visibility gate, query metrics             |
| `@cavulsqa/reactive-vue` | `useReactiveQuery` and the Framework7 page-visibility adapter        |

Do not vendor or fork them. If one is wrong, fix it there and bump the version.

## Layout

```
src/
├── app/            tabs.ts (destinations as data), theme.config.ts (seed, presets, extras)
├── router/         index.ts aggregates module routes; global/ holds the catch-all
├── domains/        <domain>/<domain>.repository.ts — SQL, no Vue
├── modules/        home, demo, gallery, settings — each {router/routes,views,components,composables}
├── shared/         components (AppPage, SectionHeader, EmptyState), composables (navigation, theme),
│                   database/, utils/
├── plugins/        framework7 (engine), m3e (services + haptics), capacitor/, i18n, sqlite
├── assets/css/     app.css (layers), theme/, layout/ (shell, transitions), base.css
└── locales/        en.json, fr.json
```

A module owns its routes, views, components and composables. A `domain` owns SQL and nothing else.
`shared` is for what two modules both use today.

## Skills and rules

| Skill                 | Reach for it when                                                      |
| --------------------- | ---------------------------------------------------------------------- |
| `m3-expressive`       | Any screen, component, layout, motion, colour or icon work             |
| `reactive-data`       | Any query, mutation, repository, migration, or a screen not refreshing |
| `module-architecture` | Adding a feature, or deciding where a file belongs                     |

Rules in `.claude/rules/`. The short version, each earned by a real bug:

- **Everything visible is an `M3*` component; Framework7 is the engine.** Five `F7*` components
  resolve (app, views, view, page, page content). See `.claude/rules/m3e-ui.md`.
- **Every routed screen is an `AppPage`.** Pushed pages pass `back`; that also hides the bar.
- **Tokens only.** Roles, the shape scale, `type-*` styles; Tailwind's own palette does not exist
  here. Hex values live in `src/app/theme.config.ts`.
- **Overlays go through the M3 services** (`useSnackbar`, `useDialog`, `useActionSheet`,
  `M3BottomSheet`, `M3Menu`) so Android back closes the top one first.
- **Icons are `<i-ms-*-rounded />` SVGs**; a wrong name fails the build, which is the point.
- **A reactive query's `tables` must list exactly what its function reads.** Under-list and the
  screen goes stale with no error. See `.claude/rules/data-fetching.md`.
- **Every write goes through `rdb`**, never `getDatabase().db`.
- **`queryKey` is an identity built from arguments**, not a label: `["demo:order", orderId]`.
- **An inserted id comes from `insertId`, never `.returning(...)`.** See `.claude/rules/database.md`.
- **Money is integer cents.**
- **`f7route` and `f7router` are props**, not imports.
- **A route loads its component through `lazyRoute`**, never a bare `import().then(resolve)`.
- **In locale files, `@` and `|` are message syntax.** A literal `@` must be `{'@'}`.
- **No comments that narrate.** A comment explains a non-obvious _why_.

## Verification

```bash
vp check          # format, lint, type-check
vp test           # repository, migration and navigation tests
pnpm type-check   # vue-tsc, the gate for anything touching .vue
```

`components.d.ts` and `auto-imports.d.ts` are generated by the dev server and the build; they are
committed so `vue-tsc` works on a fresh clone.

**Type-checking is not verification for UI.** If you changed something visual, check light and dark,
a 360dp width and reduced motion, and say plainly whether you have seen it run on a device.

## What not to do

- Do not add a state library or a data-fetching library; see the notes in `@cavulsqa/reactive-vue`.
- Do not assume the toolchain. Capacitor 8 compiles against **JDK 21**.
- Do not build for the web. `vp dev` in a browser is for inspection; the target is a device.
